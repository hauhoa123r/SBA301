UC Đã Chốt Theo DB

  • US38 - Review Courses: review courses with PENDING status before publication.
  • US39 - Approve Courses: approve qualified PENDING courses by changing status to PUBLISHED.
  • US40 - Reject Courses: reject publication of unqualified PENDING courses by returning them to DRAFT and providing a reason to the instructor.
  • US41 - Hide Courses: hide live PUBLISHED courses by changing status to HIDDEN.
  • US42 - Manage Violation Reports: use report statuses PENDING, INVESTIGATING, RESOLVED, DISMISSED.
  • US43 - Process Refund Requests: use refund statuses PENDING, APPROVED, REJECTED, PROCESSED.

DB Mapping Chuẩn

Domain DB table / enum Mapping UC Không dùng nữa
Course moderation courses.status: DRAFT, PENDING, PUBLISHED, HIDDEN PENDING = submitted for review, PUBLISHED = approved/public, DRAFT = returned for instructor revision, HIDDEN = removed from public catalog. PENDING_REVIEW, APPROVED, REJECTED cho course status.
Violation reports reports.status: PENDING, INVESTIGATING, RESOLVED, DISMISSED Receive = PENDING, verify = INVESTIGATING, resolve = RESOLVED, dismiss invalid report = DISMISSED. OPEN, IN_REVIEW.
Refund requests refunds.status: PENDING, APPROVED, REJECTED, PROCESSED Review = PENDING, decision = APPROVED or REJECTED, completed payout/admin processing = PROCESSED. PROCESSING.

Nên làm: chuẩn hóa pending status là PENDING, tạo API service frontend, bổ sung review detail panel gồm thông tin course, curriculum, lesson count, plan/tag/category, history.

Nên làm: tạo endpoint approve đổi PENDING -> PUBLISHED, ghi moderator, thời gian, audit log, và thông báo cho instructor nếu cần.

API Đề Xuất

Nhóm Endpoint Payload / Query Ghi chú nghiệp vụ
Course GET /api/courses/moderation/pending status, keyword, page, size Endpoint đọc pending đã có; có thể mở rộng response/paging sau.
Course POST /api/moderator/courses/{id}/approve optional note Chỉ cho PENDING -> PUBLISHED.
Course POST /api/moderator/courses/{id}/reject { reason } Chỉ cho PENDING -> DRAFT; reason bắt buộc, instructor cần xem được.
Course POST /api/moderator/courses/{id}/hide { reason } Chỉ hide course live/published, ghi audit.
Report GET /api/moderator/reports status, targetType, keyword, page, size Join reporter; resolve target display tùy targetType.
Report POST /api/moderator/reports/{id}/resolve { resolutionNote, action } Nếu action là hide course thì gọi chung course moderation service.
Refund GET /api/moderator/refunds status, keyword, page, size Cần trả payment, invoice, user, amount, reason.
Refund POST /api/moderator/refunds/{id}/approve / reject / process { reason } hoặc { transactionRef } Reject cần reason; process chỉ sau approved.

Thứ Tự Implement Đề Xuất

  1. Chốt status contract: giữ DB hiện tại; course dùng DRAFT/PENDING/PUBLISHED/HIDDEN, report/refund frontend đổi theo enum backend.
  2. Backend course moderation trước: vì US38-US41 chung một domain, có sẵn course entity/repository/service nên làm nhanh nhất.
  3. Thêm audit + notification: áp dụng cho approve/reject/hide để instructor/student nhận được lý do và có trace.
  4. Làm report module: repository/service/controller/DTO; resolve report có thể liên kết với hide course.
  5. Làm refund module: repository/service/controller/DTO; kiểm tra payment/invoice/subscription trước khi approve/process.
  6. Nối frontend API: thay local state bằng API service, thêm modal reason, refresh list sau action, hiển thị lỗi từ backend.
  7. Bảo vệ quyền: backend method security hoặc request matcher cho moderator/admin; frontend route guard role moderator.
